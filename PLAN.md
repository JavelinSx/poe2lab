# poe2lab — план разработки

Цель: по билду PoE2 выдавать ясную картину, что нужно для конкретной цели (DPS, EHP, контент вроде T15 корапт под делириумом):
обязательные пороги, ранжированный список статов по пользе, путь апгрейда. Позже — крафт и цены.

Принцип: **факты — из данных, математика — из PoB, LLM — только интерфейс и объяснение.**

## Этап 0 — проверка PoB headless ✅ (2026-09-21)

Результаты:
- PoB-PoE2 (коммит `ce566ea`, 2026-09-10, v0.23.1) запускается headless на Windows без WSL/Docker.
- PoB поставляется с **собственной модифицированной сборкой LuaJIT** (`runtime/lua51.dll`, поддерживает оператор `??`).
  Обычный LuaJIT код PoB не парсит. Решение: Python грузит `lua51.dll` через ctypes и держит движок у себя в процессе
  (`tools/luahost.py`).
- Старт движка ~2 с, загрузка билда ~1 с, **~350 МБ RAM** на воркер с загруженным билдом.
- Полный пересчёт `BuildOutput` — **59 мс**, what-if калькулятор — **11 мс**.
  Проход по ~150 приращениям ≈ 2 с в один поток.
- Точность на публичном билде Martial Artist 95 lvl (pobb.in/vdObLGtT-Fx1): **89 из 103** сохранённых GUI статов совпали,
  DPS совпал (205 470 vs 205 281). Расходятся Energy Shield (+12.7%) и производные (EHP, max hit), evade +1%,
  `MainHandAccuracy` отсутствует (вероятно, переименован).
  **Проверено в GUI того же коммита: ES 4156, как у headless.** Расхождение — от старой версии PoB, которой автор
  сохранял билд (pobb.in показывает сохранённые значения, а не пересчитанные).
- Сохранённые в PoB-коде статы годятся для калибровки только если билд сохранён актуальной версией PoB.
  Эталон для сверки — GUI из `pob2/runtime` (dev mode, тот же код, что и headless).
- 14 предупреждений `missing node` — безвредны (линии отрисовки дерева, на расчёт не влияют).

Открытые вопросы этапа:
- [x] Открыть тот же билд в актуальном PoB-PoE2 GUI и сравнить ES — 4156, совпало.
- [ ] Прогнать собственный билд пользователя (Martial Artist на квотерстафе) и сверить с GUI и игрой (жизнь/ES/резисты).

Точки входа в PoB, найденные на этапе:
- `HeadlessWrapper.lua`: `loadBuildFromXML(xml)`, `loadBuildFromJSON(json)` — второй принимает JSON персонажа из официального API.
- `build.calcsTab.mainOutput` — все итоговые статы.
- `build.calcsTab:GetMiscCalculator()` → what-if функция, принимает `override`:
  `addNodes`, `removeNodes`, `repSlotName` + `repItem`, `repRune`, `conditions`, `toggleFlask`, `toggleCharm`, `mainSocketGroup`, `weaponSet`.
- Пользовательские моды: `build.configTab.configSets[active].customModsList` — блоки `{title, enabled, text}`.

## Этап 1 — PoB как функция ✅ (2026-09-21)

Результаты:
- Пакет `poe2lab/engine`: `PobEngine` (загрузка кода/XML/JSON персонажа, выбор скилла, `stats()`, `what_if()`,
  выделенные ноды, логи PoB в буфер) и `EnginePool` (процессы с тёплым PoB, прогрев при создании).
- what-if одного изменения — **9 мс**, передача всех статов в Python — ~1 мс.
- Пул из 15 воркеров: прогрев ~9 с один раз, затем **~620 расчётов/с** (1050 вариаций за 1.7 с).
  8 воркеров — ~450/с, 4 — ~330/с.
- `scripts/node_values.py` — вклад каждой выделенной ноды в DPS/EHP. На билде-примере: Heavy Frost даёт ~49% DPS,
  74 ноды из 150 не влияют ни на DPS, ни на EHP.
- `tests/test_engine.py` — 8 калибровочных тестов, значения сверены с GUI коммита `ce566ea`.
- Уточнение к этапу 0: билд-пример считает Whirling Assault (205 470 DPS); Hollow Form в той же группе — 5 693.
- Слой коррекций отложен до первой найденной неточности PoB — делать его «про запас» незачем.

Исходный список задач:
1. Структура проекта: `C:\poe2lab` как git-репозиторий, `pob2` — подмодулем (не правим, обновляем через pull).
2. Пакет `poe2lab/engine`:
   - `LuaHost` (из `tools/luahost.py`) + обработка вывода Lua (не мешать с Python stdout).
   - `PobEngine`: `load_code(code)`, `load_xml(xml)`, `load_character_json(json)`, `stats() -> dict`, `what_if(override) -> dict`.
   - Выбор основного скилла (`mainSocketGroup`) — сейчас билд-пример считается по Hollow Form, а не по основному скиллу.
3. Пул воркеров: N процессов (`multiprocessing`), каждый держит тёплый PoB с загруженным билдом.
   Считать N по RAM: ~350 МБ на воркер.
4. Слой коррекций (пока пустой): версионированный под патч файл с custom-модами / Lua-патчами / пост-коррекциями,
   у каждой — какую механику закрывает и на каком патче проверена.
5. Калибровочный тест: сравнение с сохранёнными в PoB-коде статами (`tools/stage0_compare.py` → нормальный тест).

Готово, когда: одной командой прогоняются 1000 what-if вариаций билда и возвращаются 1000 наборов статов.

## Этап 2 — градиенты ✅ первая версия (2026-09-22)

Результаты:
- Тестовые билды — публичные, с pobb.in (`tests/fixtures/`, см. `tests/conftest.py`); свои билды игрока лежат
  в `builds/` и в репозиторий не попадают.
  106 из 107 статов совпали с экспортом, пользователь подтвердил совпадение с игрой.
- `PobEngine.what_if(mods=[...])` — подмешивание строк модов: what-if калькулятор перечитывает `configTab.modList`
  на каждом вызове, поэтому подменяем его копией с добавленными модами. Неразобранная строка — ошибка, а не тишина.
- `poe2lab/analysis/stats.py` — 38 статов, единица ≈ один средний аффикс; `gradients.py` — по два шага на стат
  (насыщение); метрики: CombinedDPS, TotalEHP, max hit по типам урона.
- `scripts/gradients.py` — полный проход 77 расчётов за 0.4 с в одном процессе.
- Нюанс: для скиллов с `showAverage` PoB в `CombinedDPS` отдаёт средний урон за применение, а не DPS —
  скорость атаки там не видна (так было у Rampage). Furious Slam считается в секунду.

Осталось / следующие улучшения:
- Единицы статов подобраны на глаз — сверить с реальными тирами модов, когда будет база модов (Этап 5).
- Условия из вкладки Configuration (заряды, баффы, состояние врага) напрямую влияют на результат — показывать их в отчёте.

Исходный список задач:
1. Словарь статов для перебора (~40-80): типы урона, крит шанс/множитель, скорость атаки, пенетрация, % к ES/evasion/жизни,
   резисты, атрибуты, spirit и т.д. Для каждого — строка мода и «единица» приращения (1%, 10 плоских и т.п.).
2. Механизм приращения: временный блок в `customModsList` → пересчёт → откат. Проверить, подхватывает ли его
   what-if калькулятор или нужен полный `BuildOutput` (59 мс — тоже приемлемо).
3. Метрики: ΔDPS (основной скилл), ΔEHP, Δmax hit по типам урона.
4. Два шага приращения на стат, чтобы ловить нелинейность и насыщение бакетов.
5. Вывод: таблица «стат → % прироста DPS / EHP за единицу», отсортированная.

Готово, когда: для билда-примера таблица строится за несколько секунд, и её верх выглядит разумно для игрока.

## Этап 3 — угрозы и пороги ✅ первая версия (2026-09-22)

Жалоба пользователя: на картах ваншотят хаос и физические криты, если не успевает отлечиться.

Результаты:
- `what_if(config={...}, enemy_mods=[...])` — временная подмена вкладки Configuration (уровень/тип врага, крит врага)
  и модов врага; после расчёта инпуты, плейсхолдеры и списки модов восстанавливаются.
- В PoB **нет данных о реальных ударах монстров PoE2**: общая модель врага — «средний удар» (моб 79 ур. ~113 физ.),
  пресеты боссов только из PoE1. Поэтому отчёт показывает не «что тебя убьёт», а **максимальный базовый удар
  монстра, который ты переживёшь**: обычный / крит / крит на сочной карте (+урон, +бонус крита).
- `MaximumHitTaken` в PoB учитывает моды урона врага, но не крит — крит делим отдельно на `EnemyCritEffect`.
  Базовый бонус крита монстров — +30%.
- Восстановление: лич + жизнь за удар + реген + recoup в секунду; детектор «лич упёрся в лимит на удар».
- `scripts/threats.py` — отчёт: переживаемый удар по типам, восстановление, лучшие моды для физики, хаоса и лечения.
- Важно: сохранённый билд считался против **Pinnacle-босса** (дефолт PoB). Для карт — моб 79 ур. (`--boss None`).

Ограничения / дальше:
- Уровень монстров T15 = 79 и значения «сочной карты» (+50% урона, +50% бонуса крита) — допущения, задаются флагами.
- Реальные пороги можно откалибровать только по опыту: какие удары (моб, скилл, моды карты) убивают.

Исходный список задач:
1. Жёсткие гейты: резисты 75% (и над капом с учётом штрафов контента), требования атрибутов, spirit, требования шмота.
2. Профили контента: например «T15 корапт + делириум» → минимальный EHP / max hit по типам, штраф к резистам,
   обязательные защитные слои. Первая версия — вручную, пользователь правит по опыту игры.
3. Проверка билда против профиля → список незакрытых порогов с дефицитом («не хватает 12% к холоду»).

Готово, когда: для билда-примера выводится список гейтов «закрыто / не закрыто, не хватает X».

## Этап 4 — отчёт по билду ✅ первая версия (2026-09-22)

Результаты:
- `poe2lab/analysis/report.py` + `scripts/report.py` — отчёт на русском, плюс JSON (`--json`):
  1. **Обязательно и главные дыры**: резисты (кап и запас сверх капа), хаос до капа, требования атрибутов, spirit,
     шанс попадания, типы урона слабее 50% от лучшего, реген, лимит лича.
  2. **Куда вкладываться**: рейтинг модов по цели `--mode damage|balanced|defence`. Защита — сумма прироста
     переживаемого удара по типам с весами «слабее тип — больше вес».
  3. **Путь апгрейда**: жадно берём лучший мод, считаем его применённым, пересчитываем; каждый стат один раз
     (иначе путь из шести «8% life» подряд).
- Полный отчёт ~5 с. На Титане нашёл нехватку ловкости (22 из 25) — PoB её не показывает как ошибку.
- Атрибуты как сеть зависимостей (`poe2lab/analysis/attributes.py`): источники требований из разбивок PoB
  (предметы, гемы, саппорты по цвету), что даёт каждый предмет (снимаем его через `what_if(remove_slot=...)`),
  что сломается без него, и починка переключением атрибутных нод (+5 в PoE2; считаем как `-5 to X` / `+5 to Y`).
  Проверено в игре: при 22 из 25 ловкости выключен **один** зелёный саппорт — Momentum в группе Rampage
  (группа 3; не первый по порядку и не на основном скилле). Какой саппорт игра выбирает — пока неизвестно,
  поэтому отчёт показывает цену каждого кандидата. PoB при этом считает все саппорты включёнными.
- Условные эффекты: у Momentum +40% more damage только при «Moved 2m during Skill use?»; с выключенной галкой
  PoB даёт 0%. `skill_conditions()` находит галки, привязанные к гему, и оценка саппортов идёт с ними.
- 18 тестов (`tests/test_report.py` — на Титане пользователя).

- Аудит условий (`poe2lab/analysis/conditions.py`): галки Configuration, которые PoB сам показывает для билда
  (`control:GetProperty("shown")`), переключаются по одной; в отчёте — выключенные, дающие прирост
  («PoB недооценивает, если в игре это правда»), и включённые, дающие потерю при снятии («проверь»).
  На Титане из 45 галок значимы 15: Adrenaline +36.5% DPS, Unholy/Chaotic Might +21%, Shocked +20%, Crushed +15.6%,
  Intimidated +10% DPS и +11% к переживаемым ударам. Галки основного скилла только — условия саппортов
  на других скиллах (Momentum) проверяются отдельно в оценке саппортов.

- **Ядро урона** (`core_damage` в отчёте): ресурс, на котором стоит урон, и курс статов в его единицах.
  У Титана это свирепость: в самом билде поле Rage пустое, PoB считал DPS с 0 свирепости; при полной (67) DPS ×2.31.
  `MapProfile.rage` — по умолчанию максимум (флаг `--rage`). В пробы добавлен `+N to Maximum Rage`.
- **Сравнение предметов** (`poe2lab/analysis/items.py`, `scripts/compare_item.py`): кандидат из текста PoB или из игры
  (Ctrl+C) подставляется в слот через `what_if(replace_item=...)`; дельты урона, защиты, лечения и новые дефициты
  атрибутов; `--breakeven "<строка>"` ищет, насколько можно ослабить строку, пока кандидат не хуже текущего.
  Пример: Maji Talisman +12 свирепости с теми же модами — DPS +11.6%, безубыточно до «Adds 16 to 26» (сейчас 26–42).
- Вопросы к пользователю копятся в `QUESTIONS.md`.

Не сделано из исходного плана:
- Разбивка по слотам и реальные тиры модов — это Этап 5 (нужна база модов).
- Проверка «игрок согласен с выводами» — ждёт отзыва пользователя.

Исходный список задач:
1. Итоговый отчёт: блок «обязательно» (пороги) + блок «куда вкладывать» (градиенты) + упорядоченный путь апгрейда
   с ожидаемым приростом.
2. Первая версия — глобальная, без разбивки по слотам.
3. Формат: консольный отчёт + JSON (для будущего UI/LLM).

Готово, когда: **первый полный тест** — свой билд на входе, понятный отчёт на выходе, игрок согласен с выводами.

## Этап 5 — база модов и план по слотам ✅ первая версия (2026-09-22)

Результаты:
- Данные берутся **из самого PoB** (`data.itemMods`, `data.itemBases`) — та же версия, что расчёт; внешние дампы
  и SQLite не понадобились (2 938 модов и 1 756 баз выгружаются за 0.08 с, держим в памяти).
  Ограничение: веса выпадения в данных PoB — флаги 0/1 (может/не может), настоящих весов нет → для крафта (Этап 6)
  вероятности придётся брать из другого источника или оценивать.
- `poe2lab/data/moddb.py`: шаблоны строк, тиры (T1 = лучший на этой базе), «что может выпасть на базу при этом
  уровне предмета», определение аффиксов предмета по строкам, включая гибриды. Строки, где значение выше любого тира,
  помечаются как «сумма нескольких модов» (игра складывает одинаковые статы).
- `poe2lab/analysis/slots.py` + `scripts/slots.py`:
  - вклад каждого аффикса как доля текущего билда (снятие через подмену предмета — локальные моды считаются верно);
  - **несущие** аффиксы: без них ломается spirit на резервы, требования атрибутов, кап резиста или заметно растёт
    дефицит маны; **утилити** (скорость бега, рарность, чармы…) — PoB их не ценит, к замене не предлагаются;
  - лучшие моды для базы (топ-ролл лучшего доступного тира) и действия: докрафт в свободный слот / замена слабого /
    для испорченных — что искать в замене;
  - **путь крафта по всем слотам** (`craft_path`): жадно, с пересчётом после каждого шага (хаос-резист берётся один раз),
    без шагов, ломающих капы/spirit/атрибуты/ману; билд потом восстанавливается (`engine.equip_item`).
- Находки на Титане: пять из девяти предметов испорчены; в перчатках свободен префикс, в поясе — суффикс;
  +49 spirit на амулете держит резервы; основной скилл тратит ~206 маны/с при ~96/с восстановления;
  +3 к melee-скиллам на амулет отброшены — поднимают стоимость маны (дефицит −110 → −161/с).
- 32 теста.

Ограничения / дальше:
- Счёт аффиксов приблизительный, если строки сложены из нескольких модов.
- Путь крафта — целевой набор аффиксов, а не последовательность реальных действий: случайность крафта, омены и цена —
  Этап 6.
- Мана в оценку модов не входит (только как «несущий»); см. `QUESTIONS.md`.

## Этап 6а — откуда взять мод и сокеты ✅ (2026-09-22)

Почему не полноценный симулятор крафта: экспортёр PoB берёт веса модов прямо из `Mods.dat`, и у PoE2 там только 0/1 —
настоящие веса выпадения игра на клиенте не хранит. Монте-Карло с ценой крафта без весов дал бы выдуманные цифры.
Поэтому сделано то, что опирается на реальные данные:
- `poe2lab/analysis/sources.py`: для каждого рекомендованного мода — обычный ролл (тир, нужный уровень предмета),
  эссенции, гарантирующие мод этого семейства на данный тип предмета (`data.essences`), и desecration-варианты.
  Выводится под каждым шагом пути крафта.
- `poe2lab/analysis/sockets.py`: лучшая руна / соул-кор / идол в каждый сокет. `what_if(replace_runes=...)` пересобирает
  моды рун по именам (`item.runes` + `UpdateRunes`). Учитываются запрет для испорченных (`canSocketInCorruptedSanctified`),
  уникальных, требование уровня, лимит соул-коров; «крафтовые» руны (превращают/уничтожают предмет) исключены.
- Находки на Титане: в испорченных ботинках Greater Iron Rune почти ничего не даёт — Soul Core of Tacati закроет хаос;
  в броне две слабые руны можно заменить на MoM-руну или хаос-кор.
- 35 тестов.

Дальше для крафта нужен источник весов (см. `QUESTIONS.md`); тогда — Монте-Карло с омены/эссенциями/desecration.

## Этап 12 — обобщение на любые билды (в работе, 2026-09-22)

Проверка на ma95 (монах, энергощит) показала, что часть логики заточена под атакующие билды на жизни:
1. Список статов «Куда вкладываться» (`analysis/stats.py`) — добавить урон заклинаниями, скорость сотворения,
   миньонов, % энергощита, заряды и т.п.; показывать только статы, влияющие на этот билд.
2. Выживание и лечение считаются через жизнь: у ma95 (4 156 ES) «половина жизни за inf с». Учитывать ES
   (пул = жизнь + ES, восстановление ES), убрать деление на ноль.
3. «Ядро урона» узнаёт только свирепость — распознавать и другие ресурсы (заряды силы/ярости/выносливости,
   слава и т.п.) по тому же принципу «DPS с ресурсом / без».
4. Сила поправок (аптайм, стаки) подтверждается игроком или ассистентом — оставить как есть, но предлагать
   значения по умолчанию из описаний механик.
Проверить на кастере и призывателе (нужны их PoB-коды — свои или публичные).

Сделано: п.2 — лечение учитывает энергощит (перезарядка и задержка), «inf» убран; п.1 — +17 статов (заклинания,
скорость сотворения, миньоны, снаряды, хаос, DoT, заряды, % ES и уклонения), всего 62, все разбираются PoB;
п.3 — «Ядро урона» показывает свирепость и заряды энергии/ярости/выносливости с DPS и EHP с ними и без.
Осталось: п.4 и проверка на кастере и призывателе; «лечение» в оценке модов пока только жизнь.

Проверено на публичных билдах с pobb.in (`builds/lich-minions.txt`, `builds/elemental-storm.txt`) — найдено и
исправлено:
- призыватель: DPS 0 → урон армии = урон миньона × лимит активных; рейтинг статов ведут уровни/скорость/урон
  миньонов, в «Обзоре» — «DPS армии миньонов»;
- Chaos Inoculation: бесконечный переживаемый удар ломал отчёт → иммунитет = 10⁹, исключён из «слабостей» и весов;
  переход в иммунитет и обратно считается как ±100% (иначе ключевая пассивка CI получала оценку в миллионы);
- «лечение» теперь по основному запасу: для ES — регенерация, похищение и перезарядка / (1 + задержка);
- старые гайды: базы, переименованные в новой версии игры, PoB молча выбрасывает — отчёт называет каждый такой
  предмет;
- основной скилл, который PoB не умеет считать (Elemental Storm = 0 DPS), — отчёт говорит об этом и показывает
  скиллы билда с уроном.

## Рынок, фон дерева, ревизия, приветствие ✅ (2026-09-25)

- **«🔎 Найти лучше на рынке»** в карточке слота: два поиска на pathofexile.com/trade (4 ключевых мода; вещь «под
  билд» — 5+ из 8), моды надетой вещи — не хуже 90% её значений, несущие (кап резистов, требования, скорость бега) —

  каждого поиска PoB надевает на билд; порог «лучше на N%» (15 по умолчанию) меняется без нового поиска. Цены — как
  выставлены, пересчёт в ex/div по poe.ninja; «скопировать сообщение продавцу»; ссылка на тот же поиск. Лимиты сайта

  выводы обзора, действия по слотам, профиль, провайдеры ИИ, механики и «подходит к» по-английски.
- **Приветствие и «С чего начать»**: экран с шагами и «что где», подсказки на вкладках и на значках изменений,
  карточка «С чего начать» наверху «Обзора» (что сломано → главная слабость → самый выгодный мод, со ссылкой на вкладку).
- Обязательная фраза GGG («not affiliated with or endorsed by Grinding Gear Games») — в боковой панели и README.
- **Утечка памяти**: состояние Lua движка PoB никогда не закрывалось — каждое открытие билда (и эталона для

## Идеи на очередь (2026-09-25)

1. **Прайсчек по горячей клавише** (как оверлеи Overwolf): F-клавиша на вещи в игре → poe2lab сравнивает её с надетой
   через PoB и ищет похожие на рынке — «для билда +X%, на рынке такие стоят ~Y». Машинерия поиска уже есть.
2. **Бюджет апгрейда**: «у меня N div — что купить первым» — поиск по всем слотам и рейтинг «прирост на divine».
3. **Поиск замены для уников и пустых слотов** (сейчас — только редкие и магические вещи) и третий вид поиска —
   «взвешенная сумма» модов, как у PoB, с потолком цены.
4. **Лут-фильтр по рынку**: подсветка дорогих валюты и уников по poe.ninja (ждёт ответа про пороги в div/ex).
5. **Проверка карты**: вставил моды путевого камня — «эти моды для твоего билда опасны» (отражение, без регена,
   −макс. резисты) с расчётом PoB.
6. **Самоцветы в дереве**: какие моды самоцвета дадут больше всего в каждом гнезде, и их поиск на рынке.
7. **История билда**: было/стало после «обновить» — что изменилось и насколько.
8. **Экспорт отчёта** страницей, чтобы показать билд другу или в гайде.
9. **Флаконы и чармы** в «Снаряжении» (сейчас пропускаются).
10. **Готовые данные игры вместе с программой** (тексты, иконки), чтобы работало без установленной игры.
11. **Общий журнал крафта**: веса модов из записей многих игроков.

- PoB отстаёт от патча или не моделирует механику (например, колокола Martial Artist) → слой коррекций,
  прицельно для статов, от которых механика зависит (колокола → крит).

  обновлять осознанно, прогонять калибровочный тест.
- Правила крафта меняются каждый патч → основная постоянная нагрузка этапа 6.
